# Best Practices dataset: source-file migration

## Summary

The Best Practices Explorer (in both `app.py` and the `frontend/` React
dashboard) is driven by a CSV export of the AFU Best Practices form/Airtable
base — one row per submitted activity. As of 2026-08-25 the canonical source
file is:

```
Form Data Entry-Grid view.csv
```

replacing the previous:

```
Form_Data_Entry-Grid_view.csv   (deleted)
```

Two additional files that were briefly present in the repo root —
`Form Data Entry-Gallery (1).csv` and `Form Data Entry-Gallery (2).csv` —
have also been removed. They were **not** a newer dataset: they were an
export of the same 31 activities taken from Airtable's "Gallery" view, which
only exposes 4 of the base's 15 fields (Title, Principle(s), Audience,
Purpose). Switching to them would have silently dropped the University,
Type of Activity, Outcomes, Uniqueness, Duration, Challenges, Links, and
Images fields that the Best Practices Explorer depends on. They're noted
here only so a future re-export from the Gallery view isn't mistaken for
fresh data again.

## What actually changed between the old and new Grid view files

Row-by-row diff of `Form_Data_Entry-Grid_view.csv` (old, dated 2026-08-13)
against `Form Data Entry-Grid view.csv` (new, dated 2026-08-25) found:

- **Same 31 activities**, same headers, same 15 columns — no rows added or
  removed, no field content rewritten.
- The only differences were:
  - Airtable's signed attachment URLs in `[If Applicable] Submit Images of
    The Work` (these tokens rotate on every export; expected and harmless —
    `app.py`/the frontend only display the filename portion, not the URL).
  - `\r\n` → `\n` line-ending normalization inside a few multi-line text
    fields (`Relevant Links or References`, `What have the outcomes been to
    date?`, etc.) — a re-export/download artifact, not a content change.

So this migration is a **drop-in replacement of an older export with a
newer one from the same source**, not a schema or content change.

## Why the filename changed (underscores → spaces)

The old file's name (`Form_Data_Entry-Grid_view.csv`) used underscores in
place of spaces. Airtable/the form tool names CSV exports after the
table and view (`"<Table Name>-<View Name>.csv"`); the new export's
literal spaces (`Form Data Entry-Grid view.csv`) are almost certainly what
the export tool now produces given the current view name. Rather than
rename the file into the old underscore convention, the code was pointed at
the file as exported — future re-exports (as long as the Airtable view
keeps its current name) should land under this same filename, so no
renaming step should be needed for routine data refreshes going forward.

## Files updated to point at the new source

| File | Change |
|---|---|
| `app.py` | `load_best_practices()`'s `csv_path`, plus two user-facing warning/error strings that named the file | `Form_Data_Entry-Grid_view.csv` → `Form Data Entry-Grid view.csv` |
| `frontend/scripts/sync-static-data.mjs` | `buildBestPractices()`'s `readFileSync(...)` path | same rename |
| `frontend/public/data/best_practices.json` | regenerated by re-running `node scripts/sync-static-data.mjs` | now built from the new CSV |
| `CLAUDE.md` | doc reference to the CSV filename | same rename |
| `NEW_FRONTEND_PLAN.md` | data-flow table entry | same rename |

No column-name lookups (`findCol`/`[c for c in df.columns if ...]` in
either `app.py` or `sync-static-data.mjs`) needed to change — the new file
has identical headers to the old one, just newer field values and refreshed
attachment URLs.

## Routine data refresh procedure (going forward)

1. Re-export the Airtable base's **Grid view** (not Gallery — Gallery drops
   11 of the 15 fields the Explorer needs) to CSV.
2. Save it over `Form Data Entry-Grid view.csv` in the repo root, keeping
   the exact filename so no code changes are needed.
3. From `frontend/`, run `node scripts/sync-static-data.mjs` to regenerate
   `frontend/public/data/best_practices.json` for the React dashboard.
   `app.py` needs no separate step — it reads the CSV directly at runtime
   (via `st.cache_data`, so restart/rerun the Streamlit app to pick up the
   change).
4. If Airtable's view is ever renamed, the exported filename will change
   too — update the path in `app.py` and
   `frontend/scripts/sync-static-data.mjs` (and this doc) to match.
